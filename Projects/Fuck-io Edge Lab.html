Session log

    The detector, as it will run on the ESP32

    every 20 ms (50 Hz):
  p      = read sensor on GPIO 34, 4x oversampled, in kPa
  fast  += (p - fast) * dt / 0.06            // knock off ADC noise
  delta  = fast - base
  if delta < sensitivity or above it for > 3 s:
    base += (fast - base) * dt / baseWindow  // slow baseline, held still during clenches
  if delta > sensitivity:
    score += (delta - sensitivity) * gain    // only the bit above the line counts
  score *= exp(-dt / decay)

  running  and score > threshold            -> stop, start cooldown
  cooldown done and score < threshold * resume -> ramp back up from zero

    The body model is invented but shaped like the real thing: clenches get stronger and more frequent as arousal climbs, there is a point of no return a few seconds before orgasm, and orgasm shows up as 8 to 12 contractions about 0.8 s apart. The detector never sees the true arousal line. It only sees pressure.

    • Thrust bleed is the machine itself pushing on the plug every stroke. Turn it up and watch the score creep without any clenching.
    • Shift position moves the baseline. The freeze rule stops a single clench dragging the baseline up, and the 3 s limit stops a real position change from freezing it forever.
    • Early stops are edges called below 60% true arousal. Slipped means the detector stopped too late, after the point of no return.
    • Switch the sensor between the 0-40 and 0-100 kPa versions to see the difference in resolution on the trace.
