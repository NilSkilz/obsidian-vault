# DIY Veo (rugby match camera)

Goal: Veo-style auto-panning match footage of Dexter's rugby for ~£0-180, no £75/month subscription. Two cameras film the whole pitch, software stitches a panorama and an AI "camera" crops/pans to follow play.

## Software: reco video-stitcher
- Open source (AGPL), Rust rewrite: https://github.com/reco-project/video-stitcher (repo cloned at `/home/jarvis/projects/video-stitcher` for reference)
- Prebuilt GUI app, no build needed. Latest v0.5.4 (Aug 2026):
  - Mac (Apple Silicon): use the **ffmpeg9 build**: https://github.com/reco-project/video-stitcher/releases/download/v0.5.4/reco-gui-v0.5.4-macos-arm64-ffmpeg9.tar.gz, plus `brew install ffmpeg` (Homebrew ships FFmpeg 9.0.2 as of Oct 2026). The plain `macos-arm64` build links libavutil.60 (FFmpeg 8) and dyld-aborts on Rob's Mac (hit 05 Oct 2026).
  - AI tracking model (same page): `yolo26n.onnx`
- Workflow per QUICKSTART: load left+right video, Auto Calibrate (feature match + audio sync), fix lens via Gyroflow profile browser if warped, set ROI polygon per camera, export 1080p with AI tracking (Field mode, detection interval 15).
- Jarvis's box CANNOT be the render node: LXC has no GPU and the prebuilt Linux CLI needs FFmpeg 6 (libavutil58) vs Debian 13's FFmpeg 7. Processing lives on a Mac/desktop with a real GPU. (Verified 05 Oct 2026.)

## Hardware decision (as of 05 Oct 2026)
- Pilot: two iPhones (11+), ULTRA-WIDE lens (~120° each), 4K30, locked exposure (Blackmagic Camera app), case off, airplane mode, ~45GB free each. This is literally what Veo Go sells.

- **Five porting gotchas (cost real debugging time, don't relearn):**
  0. The streaming mp4box demuxer silently indexes ZERO samples on moov-at-end files (ffmpeg's default layout; iPhone exports are faststart, which is why the sofa clips never showed it). "Video track contains no samples" = this. Fixed 05 Oct (touchline 84e09f7): `pumpThroughMp4Box` in `lib/demux.ts` does a second pass from `mp4.seek(0, true).offset` when the first pass yields nothing; regression guard is `scripts/e2e-moov-at-end.mjs`. Anything we mux ourselves gets `-movflags +faststart`.
  1. Emscripten MODULARIZE puts a fake thenable `then` on the module object. Resolve any promise with it (e.g. return it from an async function) and the thenable resolves with itself forever: the worker's microtask queue spins and the thread hard-blocks with no error. `delete cv.then` after init.
  2. The optimizer's plane coordinates span the FULL doubled quad (the shader's 2x overscan), with the source image in the central half. Reco detects on undistorted frames that cover that whole quad, so raw-pixel matches must map pixel -> KB4 undistort -> plane UV u -> quad UV (u+0.5)/2 before `normalizeToPlane`. Feed it plain undistorted UV and the optimizer happily converges to a layout that renders ~550 px off.
  3. onnxruntime-web's default "bundle" build, imported inside a worker, spawns its pthread sub-workers from OUR worker chunk URL and dies with `multiple calls to initWasm()`. Fix: select the extern-wasm build via vite `resolve.conditions: ['onnxruntime-web-use-extern-wasm']` and vendor the runtime under `public/ort/` (`env.wasm.wasmPaths`).
  4. SwiftShader "WebGPU" initializes an ort webgpu session fine, then infers at ~96 s/frame (vs 0.66 s wasm on the same box). The worker time-boxes webgpu session creation and falls back to wasm; the headless e2e forces the wasm EP outright.
  5. A timed-out (abandoned, still-pending) ort `InferenceSession.create` leaves the wasm runtime stuck mid-init, so ANY later create in that worker context throws `multiple calls to 'initWasm()' detected` (users see "no available backend found"). Rob hit it 05 Oct: the 30 s hang timeout was also timing the ~38 MB model+runtime download, so a slow first load on a real GPU tripped it and the in-context wasm fallback died. Fixed (touchline 8ac3be9): model prefetched + jsep binary handed to ort via `env.wasm.wasmBinary` (timed window is pure compile, now 20 s), a timeout fails the init instead of falling back in-context, and yoloClient terminates + respawns the worker and retries once on plain wasm. Regression stage in `scripts/e2e-yolo.mjs` (simulated hang). Rule: never run a second ort create in a context where one may still be pending; recover in a fresh worker.
